# Deepresearch 提炼 Skill

把「第三方参考」（开源仓库、论文、芯片手册）转成 EchoGlove 科研级原理文档，写入 `/home/EchoGloveHugeProjects/third-party-deepresearch/research/`。

## 触发条件

- 用户说要参考某第三方项目 / 论文 / 手册来做设计或架构决策
- 用户要新增一篇 `research/*.md`
- 用户要更新现有 `research/*.md`（对接新论文）

## 铁律：隔离规则（先于任何提炼动作）

1. **原始源码永不进检索**：第三方源码只存在于 `third-party-deepresearch/repo/`（gitignored）。禁止对其跑 `codebase-memory index_repository`、`graphify update` 或语义检索。核对 API 细节时**定点 Read 单文件，读完即弃**，不纳入推理基线。
2. **提炼结果才暴露**：只有 `research/*.md`（版本化、可检索、被 MCP 允许）承载第三方知识。
3. **不抄代码**：提炼 ≠ 翻译。判据——这条信息 6 个月后还有用吗？有用 → 进 research/；只是本次实现临时细节 → 留在 repo/ 定点查阅；都不是 → 丢弃。
4. **产品仓免疫**：产品仓（EgoGlove / EchoGlove-SLR-MOCAP-Beta）内不放置任何第三方源码副本。若必须在仓内临时放参考，先确认 `.gitignore` + `.claudeignore` 双忽略，用完即删。

## 五要素模板（每篇 research/*.md 必须覆盖）

1. **核心算法公式**：LaTeX（`$$` 块 / `$` 行内），变量名与代码一致；标注出处章节/行号。
2. **数据结构 / 通信协议定义**：帧格式偏移表、f16/f32 编码、CRC 多项式、字节序等，逐字节精确。
3. **硬件拓扑图**：科研级 ASCII（标注 GPIO/I²C 地址/总线速率/电源约束）。
4. **关键 API 签名**：只摘接口契约（入参/出参/前置条件/返回码），不摘实现体。
5. **工程踩坑记录**：符号错误、单位不匹配、寄存器配置陷阱、I²C/时序坑——每条附一句「为什么」+ 修复方式。

## 真实性四级标注（每能力段首）

| 符号 | 含义 |
|------|------|
| ✅ | 已实现 / 板上验证 |
| 🟡 | 工程可实现（6–12 月） |
| 🔬 | 需研发验证（无真实数据/权重） |
| 🌌 | 长期方向 |

未核实内容必须写「待人工核对」，禁止用模型先验冒充已核实事实。

## 显式溯源（每篇必须）

- 上游仓库 URL + commit/版本（或论文 arXiv ID / 手册版本）
- 对应文件路径（`file:line` 可点击）
- 提炼日期 + 提炼人（`PaxonHuang <quenchkidney@outlook.com>`）

## 产出质量门

- 单篇 5–20KB（健康密度）。>100KB 就该拆主题。
- ASCII 网络图必须标注张量维度 `(B, T, N, C)`。
- 内容需与产品仓实际代码/设计文档交叉核对，标注真实性与产品仓文件的对应关系。
- 新篇须在 `research/index.md` 更新目录 + 真实性总表 + 关键决策记录。

## 反模式

- ❌ 每第三方项目各建一个 skill（撑爆注册表、增加触发噪音）
- ❌ 把第三方仓库 clone 进产品仓
- ❌ 对 `repo/` 或 `paper/` 建代码图索引
- ❌ 在提炼文档里写「参考某实现」却不给版本号（不可复现）
- ❌ 将商业敏感内容（如 `BP/`）写入公共仓
